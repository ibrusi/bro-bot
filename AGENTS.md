# Системные настройки и инструкции проекта bro-bot

Ты — интеллектуальный агент, работающий с кодовой базой проекта `bro-bot`. При выполнении любых задач ты должен строго следовать описанным ниже инструкциям и использовать актуальные переменные окружения.

## Переменные окружения (.env)
Считывай параметры из файла `.env` при необходимости.

**ВАЖНОЕ ПРАВИЛО БЕЗОПАСНОСТИ:**
Ты должен знать о существовании параметра `TELEGRAM_BOT_TOKEN`, но тебе **строго запрещено** считывать, выводить или сохранять его значение. Все остальные параметры из файла `.env` считывать разрешено.

Список основных переменных, которые есть в проекте (значения бери из `.env`):
- **TELEGRAM_BOT_TOKEN**: *[значение скрыто, не читать и не сохранять]*
- **TELEGRAM_ADMIN_ID**
- **PROJECTS_ROOT**
- **DEFAULT_PROJECT**
- **DEFAULT_MODEL**
- **STEP_TIMEOUT**
- **QUESTION_TIMEOUT**
- **BOT_DIR**
- **BOT_SERVICE_NAME**

## Инструкции для автономной работы
Строго соблюдай следующий рабочий процесс:

0. **Режим планирования**:
   - Если в задаче указано, что выполняется этап планирования, НЕ создавай git-ветку, НЕ меняй файлы проекта, НЕ делай commit/push и НЕ открывай PR. Сформируй и выведи подробный, пошаговый план реализации задачи для утверждения пользователем.

1. **Ветка**:
   - Проанализируй задачу и создай ветку от актуального `main`: `feat/краткое-описание` или `fix/краткое-описание`.

2. **Разработка и проверка**:
   - Внеси изменения в код.
   - Запусти линтеры или тесты проекта, чтобы убедиться в работоспособности.

3. **Коммит**:
   - Сделай git commit по стандарту Conventional Commits.

4. **Pull Request**:
   - Запушь ветку: `git push -u origin HEAD`
   - Открой PR через GitHub CLI:
     `gh pr create --fill`

5. **Итог**:
   - В самом конце своего ответа обязательно выведи строчку строго в формате:
     `PR_URL: <полная web-ссылка на созданный PR>`

6. **Вопросы**:
   - При неоднозначности требований или нехватке параметров НЕ придумывай логику сам. Задай через инструмент `ask_question` конкретный вопрос человеку и жди ответа.
   - Это не ограничение "один вопрос за всю задачу": получив ответ, продолжай выполнение, и если снова возникнет неясность — задавай следующий уточняющий вопрос. Так можно вести диалог столько раз, сколько потребуется: каждый вопрос лишь ставит задачу на паузу до ответа, а не прерывает и не проваливает её.
